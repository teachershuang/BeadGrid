# BeadGrid 封版功能设计

## 目标

在现有“导入图片、自动生成、预览、导出”链路上补齐三个封版能力：手工修图、工程文件保存与恢复、PDF 打印版导出。三个能力必须共享同一份当前图纸数据，确保预览、统计、采购清单和所有导出结果一致。

## 范围

### 1. 手工修图

- 图纸预览提供“查看”和“修图”两种模式。
- 修图模式可从当前品牌完整色板选择画笔色号，也可选择橡皮擦把格子设为空珠。
- 支持单击和按住拖动连续修改，单次拖动作为一条历史记录。
- 支持按钮和 `Ctrl+Z`、`Ctrl+Y` 撤销/重做，最多保留 100 条操作。
- 支持“一键恢复自动生成结果”。恢复前的当前状态进入历史记录，因此仍可撤销。
- 每次修改后立即重算颜色用量、空珠数、实际颜色数；现有 PNG、ZIP、CSV 和新增 PDF 均导出当前结果。
- 查看模式保持现有点击高亮、悬停坐标和色号读取行为。

### 2. 工程文件

- 使用自包含的 `.beadgrid` JSON 文件，不依赖原图所在路径。
- 工程文件包含格式版本、保存时间、原图名称、PNG Data URL、生成参数、自动生成基线和当前图纸。
- 未生成图纸时也可保存原图与参数；生成后保存时同时保留手工修改和恢复基线。
- 打开工程后恢复原图、参数、预览模式、当前图纸和自动生成基线，并清空撤销/重做历史。
- 读取时校验格式版本、尺寸、格子数量和关键字段；损坏或未来版本文件显示中文错误，不覆盖当前工作区。
- 文件格式版本固定为 `1`。未来结构变化必须新增迁移逻辑或明确拒绝，不静默误读。

### 3. PDF 打印版

- 新增“导出打印版 PDF”入口。
- PDF 使用 A4 纵向页面，每块底板一页，按从上到下、从左到右排序。
- 每页复用底板拆分图的色块、色号、坐标、`5×5` 红色分界和底板边界。
- 页面内容先由 Canvas 完整绘制，再作为 PNG 放入 PDF，避免 PDF 内置字体缺少中文。
- PDF 页数等于底板拆分数量；边缘不足整板的页面保留实际宽高。
- 浏览器和 Tauri 均通过现有保存抽象下载 `.pdf` 文件。

## 架构与文件边界

- `src/core/pattern/patternEditor.ts`：纯函数应用格子修改、生成撤销命令、撤销/重做和重算统计。
- `src/core/project/projectFile.ts`：工程文档类型、序列化、解析和数据校验，不访问 DOM。
- `src/core/project/sourceImageCodec.ts`：在 Canvas 与 Data URL 之间转换原图像素，只处理浏览器图像编码。
- `src/core/export/printPlan.ts`：把底板拆分计划转换为稳定的 PDF 页面计划。
- `src/core/export/exportPdf.ts`：调用图纸 Canvas 渲染器和 `jsPDF` 组装 PDF，再走现有保存接口。
- `src/components/PatternPreviewCanvas.tsx`：增加修图指针事件，只负责把指针位置转换为格子索引，不持有历史状态。
- `src/pages/HomePage.tsx`：编排当前图纸、自动生成基线、画笔、历史、工程打开/保存和 PDF 导出。

## 数据流

1. 自动生成完成后，同一个结果分别写入“自动生成基线”和“当前图纸”。
2. 指针修图产生一个或多个格子修改，编辑器返回新的当前图纸并重算统计。
3. 一次指针按下到抬起合并为一条命令，进入撤销栈并清空重做栈。
4. 所有预览和导出只读取当前图纸。
5. 保存工程时编码原图并同时写入基线和当前图纸；打开工程必须先完整解析成功，再替换页面状态。

## 错误处理

- 越界格子修改被纯函数拒绝，界面不会创建历史记录。
- 重复涂抹相同颜色不修改图纸、不增加历史记录。
- 工程文件解析失败、图像解码失败或 PDF 生成失败统一进入现有错误提示区域。
- 用户取消打开或保存对话框不视为错误。
- PDF 没有图纸时按钮禁用。

## 测试策略

- `patternEditor`：单格修改、批量修改、空珠、统计排序、重复修改、撤销和重做。
- `projectFile`：往返序列化、无图纸工程、版本拒绝、格子数量错误、无效 JSON。
- `printPlan`：页面数量、顺序、边缘底板尺寸和文件标题。
- 现有全部单元测试、TypeScript 构建和 ESLint 必须通过。
- 浏览器实测：加载样图、生成、拖动修图、撤销/重做、保存并重新打开工程、导出 PDF。
- Tauri 构建至少完成 Rust/桌面打包验证；若本机工具链阻塞，必须保留前端验证证据并报告准确原因。
